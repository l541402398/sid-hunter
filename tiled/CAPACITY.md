# 200–300 人同层容量测算（房间版 + 5F 迷宫）

日期：2026-10-18
口径：1 格 = 16px 美术 = 32×32 world px ≈ 1m²。下表用「实际可达格」计算（扣掉 props/门框阻挡）。

## 逐层容量

| 层 | 实际可达格 | 200 人/层 | 300 人/层 |
|---|---:|---:|---:|
| 1F | 1289 | 6.4 m²/人 | 4.3 m²/人 |
| 2F | 1347 | 6.7 m²/人 | 4.5 m²/人 |
| 3F | 1297 | 6.5 m²/人 | 4.3 m²/人 |
| 4F | 1401 | 7.0 m²/人 | 4.7 m²/人 |
| 5F | 877 | 4.4 m²/人 | 2.9 m²/人 |
| 6F | 1335 | 6.7 m²/人 | 4.5 m²/人 |
| 7F | 1397 | 7.0 m²/人 | 4.7 m²/人 |
| **合计** | **8943** | **44.7 m²/人**（全楼均摊） | **29.8 m²/人** |

> 参考：站立人群约 0.5–1 m²/人；舒适社交/走动约 2–4 m²/人；5 m²/人以上属于宽松。
> 1F–4F/6F/7F 仍是房间版（2 格环廊 + 2 格隔墙）；5F 改成 1 格宽走廊迷宫 + 石室，可走率 39.1%，厚墙 19.6%（迷宫墙）。
> **300 人全挤同一层**约 2.9–4.7 m²/人，5F 迷宫拐角会明显拥堵；**200–300 人分散在 7 层**每层 29–43 人，约 30–45 m²/人，很宽松。

## 动线

- 主路径/环形走廊保持 **2 格 = 64 world px**，不是 3 格；功能区隔墙 2 格厚，保留结构柱/设备间，空间更封闭。
- 每个功能区 **2 格宽门洞 + 2 格深 L 形通道**；比 3 格开放版窄，但 7 层分流后 300 人仍可用。
- 装饰 props 全部 `solid:false`，不占实际可达格；门框/实心 landmark 仍挡人。

## 出生点

- `floorSpawns` 上限 **1024**，300 人也有独立出生点。
- 服务端 `spawnPointFor()` 用乘法步长 `index × 2654435761 mod pool.length`，不再让前 300 人全落在“最靠近 spawn 的 300 个点”。
- 出生点仍全部来自 `collision=0` 且不被 props 占用的格子。

## 边界

- 这里算的是**地图容量**，不是服务器承载：300 人 × 20Hz SSE、tick、AOI、网络带宽需要单独压测。
- 3 格开放版（65.6–68.8% 可走）已回退，因为房间感太弱、像仓库；如果后面要办 300 人单层活动，再单独开临时大平层，不要改常驻 7 层。
- props 在 200–300 人模式下多为**非阻挡装饰**，可在 Tiled 里逐件改回 `solid:true`。

## 复跑

```bash
node tiled/build-floors.mjs
node tiled/validate-floors.mjs   # 空地率 55–64% / 实际可达 52–64% / 厚墙 ≤12%
node tiled/validate-extra.mjs    # 装饰成组 + 1F/7F 素材键/文件 + 80–110 件
```
