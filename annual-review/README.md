# 我的 2026 · 年度纪念册

游戏主页中的年度纪念册弹窗，以合上的精装书为封面。点击开启后展开成双页，通过带正反面、书缝轴心和阴影的 3D 翻页阅读内容。关闭或 Esc 合书退出后直接露出同一页面里的游戏，工具栏“年度纪念册”可以再次打开。使用原生 HTML、CSS、Canvas 和 Web Animations，无构建依赖。

## 本地预览

在项目根目录运行集成预览：

```powershell
node annual-review/serve.cjs
```

访问 <http://127.0.0.1:8790/>，进入时显示纪念册，关闭后进入真实游戏主页。可通过 `REVIEW_PORT` 修改预览端口。启动器仅绑定本机，使用昵称试玩与独立的 `outputs/annual-review-game-preview/sid.sqlite` 存档，并开启本地预览场；不读取既有游戏存档。

正式游戏继续使用 `node online/server.js` 和原有登录、存档配置。`/annual-review/` 只读托管纪念册资源；父页面以同源 iframe 隔离纸面样式，消息校验来源窗口和同源地址。弹窗打开时暂停游戏输入与背景画布绘制，保留联网快照、状态插值和计时更新；合书后在淡出开始时恢复背景绘制，让游戏自然露出，输入在弹窗关闭后恢复，不刷新、不导航、不销毁游戏。直接打开本目录 `index.html` 仍可独立查看书本，集成体验请使用游戏根地址。

## 内容与交互

1. 合上的年度纪念册封面。
2. 开篇双页：致同行者、慰问致辞、回顾引导语。
3. 榜样人物：按 `mock/榜样数据.xlsx` 的顺序展示 20 个事项，5 组双页，每组 4 项、左右页各 2 项；共 22 获奖人次、19 位员工。双人事项在同一张卡片展示两人的姓名、工号及该项数据，不拆开或重复计算。头像为示意头像，不显示“读 TA 的故事”入口。
4. 我的 2026：个人身份、年度指标和个人回忆。
5. 结束寄语。

默认手动翻阅，不自动跳页。鼠标点击左页向前翻、右页向后翻，点击封面也可开启；底部箭头、书页外下角和左右方向键同样可用。选择文字及点击页内按钮时不会触发整页翻页，翻页期间禁用重复操作。侧边书签跳转章节，Home／End 跳到开篇／结束。封面属于翻阅顺序的一部分：开篇双页继续向前翻，会合上书并停留在封面，再次开启从开篇开始。左页数字页码位于左下角，右页位于右下角，底部导航与书本留出独立间距。榜样章节的每个单页使用独立引导标题，不展示组数；标题在 `content.js` 的 `peoplePageTitles` 中按阅读顺序配置。

使用右上角关闭按钮或 Esc 退出时，先完成正在进行的翻页或开合，再从当前双页合书，淡出弹窗后重置阅读状态。重新进入和刷新都回到封面，开启后从开篇开始；不保存阅读进度，早期版本的进度缓存会自动清除。封面不设置“稍后回顾”入口，左上角不展示“内容示例”标签。

封面使用温暖的胡桃棕皮革、细金边和弧形书脊阴影，搭配柔和边缘光、四周暗角与底部悬浮阴影。书脊有竖向暗金英文，右上长书签有夹入书页的投影。藤蔓、叶簇与暖白小花缠绕左上角和右下角，枝条两端藏入书后，右下装饰稍收拢。年份、书名与顶部小字使用清晰的浅金色，中部散布低亮度金色星尘；左下 CQRD 藏书印通过透明底、柔和内阴影和双向文字光影呈现压花。“开启年度回忆”按钮位于画面中下部，细描边与内阴影表现凸起金属铭牌；JULI 靠近按钮右下方，脚底软影与窄接触影让人物落在书封上。周围深色背景散布细小星光和少量四角闪星，动画与 JULI 一样仅在封面可见时播放，进入内页、关闭或切换浏览器标签后暂停。

系统开启“减少动态效果”时，直接展开和切页，不播放翻书、JULI 与光点动画。电脑窗口已覆盖 1280×720、1440×900 和 1920×1080，保持双页阅读。

展开后的书本保留轻微俯视角度，左右纸面各有对称的小幅夹角；两页顶边、底边及纸堆厚度保持一致，翻阅各章均使用相同厚度，避免书缝底部出现高低台阶。书脊附近的曲光、凹槽阴影与分层纸边区分纸面、纸堆和硬壳，正文区域保持清晰。书页使用细金双线花边、镜像角花及低对比纸纹，装饰集中在边缘和留白。

书本开合使用同一动画时间轴同步封面铰链、左半书背、整书居中位移、纸堆厚度与书缝阴影。右半书背始终保留，左半边框随封面转动，避免结束时重新补画整圈边框；书缝阴影随角度连续变化。旋转内侧与静止左页使用相同几何尺寸及纸面光影，开合期间只显示旋转内侧，避免文字叠影。翻动纸页使用连续曲面，外沿先抬起，弧度延伸进纸面，再随翻转落回纸堆；卷曲、转动及明暗共享同一时间轴，前后翻方向相反，起页与落页均恢复平整。32 段曲面、正反纸面、阴影和 1080ms 时长保持一致；关节角使用不继承的局部动画属性，光带直接动画透明度，避免逐帧向正文子树传播参数。相邻页在空闲时分段准备，最多缓存三组离线卷页；尺寸沿用当前 CSS 计算，挂载时只显示当前一组，完成或中断后取消所有动画并移出页面，退出清空缓存。翻页、开合的首尾都匹配展开时的纸面夹角，动画按真实完成事件收尾。

## 素材与内容替换

- 封面邀请图来自用户指定的 `sid-hunter-main-ui_assets/首页-JULI形象设计/邀请图.png`，原样复制至 `assets/juli-invitation.png`，不镜像、不重绘。内页黄色 JULI 仍使用 `assets/juli-yellow-sheet.png`，由 Canvas 从原三视图中呈现正面。
- `people.mock.js` 保存从 `mock/榜样数据.xlsx` 的“榜样数据”工作表导出的榜样事项；`content.js` 配置寄语、引用榜样数据并配置个人回顾。
- Excel 列顺序为“序号、事项、数据、单位、姓名 1、工号 1、姓名 2、工号 2”。第 9 项“认证追光者”和第 12 项“评优‘显眼包’”各有两名员工；单项只有一份数据，不解释为两人合计或自行拆分。
- Excel 的单位列按原文展示，如“次、行、条、小时、粒”；百分比显示格式也会保留：采纳率 `0.57` 显示为 `57%`，文本工号保留前导零。卡片左侧为头像，右侧依次展示姓名、工号、重点标题和大号数据＋单位。工作表未提供的单位、人物故事和真实头像不另行生成。
- 修改 Excel 后，在项目根目录运行 `python annual-review/scripts/import-people.py` 重新导出；脚本仅使用 Python 3 标准库，不需要安装依赖。导出的 JS 随代码发布，浏览器不读取 Excel。
- 榜样事项可增减，页面按每组 4 项自动分页；最后一组不足 4 项时保持左右页布局。事项字段为 `label`、`value`、`unit`、`winners`；每位员工含 `name`、`employeeId`，可另提供 `avatar` 图片路径，未提供时使用示意头像。同一工号在不同事项使用相同示意头像。
- `personal` 配置当前员工的年度回顾；暂无数据时可设为 `null`，展示资料整理中的状态。
- 榜样章节使用本次 Excel mock 数据，个人回顾、署名和致辞仍为静态示例，不读取游戏玩家的真实年度数据，也不会因登录游戏而自动切换为正式资料。
- 本版仅包含榜样人物和个人回顾，无公司项目回顾章节。

## 文件职责与验证

`index.html`：书本结构；`styles.css`：纸张、卷页与基础排版；`cover.css`：封面邀请构图、藤蔓与圆润书棱；`honors.css`：榜样卡片；`ornaments.css`：内页花边与底纹；`content.js`：内容数据与引导标题；`art.js`：原图呈现和像素办公室；`app.js`：阅读与翻页；`serve.cjs`：本地集成预览启动器。游戏侧入口位于 `online/public/js/annual-review.js`，弹窗容器样式位于 `online/public/styles/annual-review.css`。

检查脚本保存在 `annual-review/tests/`，无 npm 依赖：

```powershell
node --test annual-review/tests/static-routes.test.cjs
node annual-review/tests/reader.browser.mjs
node annual-review/tests/integration.browser.mjs
node annual-review/tests/focus.browser.mjs
```

浏览器检查前先运行本地集成预览。脚本使用已安装的 Chrome、Chromium 或 Edge，可通过 `CHROME_BIN` 指定浏览器路径。`--url` 或 `REVIEW_URL` 可覆盖待测地址：阅读器检查默认 `/annual-review/`，游戏集成和焦点检查默认游戏根地址。完整阅读器检查包含封面、榜样数据、卷页、退出及减少动态效果；也可按需运行：

- `reader.browser.mjs --cover-only`：三种桌面尺寸的封面布局、图片完整性和开合。
- `reader.browser.mjs --symmetry-only`：三种桌面尺寸的纸面、装订与书堆对齐及装饰资源。
- `reader.browser.mjs --exit-only`：关闭按钮和 Esc 在展开、合书、翻页过程中安全退出。

截图、报告、浏览器临时目录和本地备份统一保存在被 Git 忽略的 `outputs/`。JULI 原始素材包、未接入的设计稿和生成过程临时文件也仅留在本地；实际运行需要的图片与 SVG 均位于本目录 `assets/`。Docker 镜像包含运行资源，不包含预览启动器或检查脚本。
