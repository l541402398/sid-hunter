## 2. 核心做法：楼板加宽，但**像素尺度零变化**

原每层 `960 × 400` 世界像素（30m×30m，横向恰好一屏）。本轮加宽到 **`1440 × 400`（45m×30m，1.5×）**。

关键点：**不重新排版、不改变任何家具/角色/门洞的像素尺寸**。做法是把 x 轴归一化空间由 `0–1000` 扩到 `0–1500`：

```js
const FLOOR_W = 1440, FLOOR_H = 400;      // 原 960×400
const X_SPAN = 1500, Y_SPAN = 1000;       // x 设计跨度 1000 → 1500
const nX = v => Math.round(v / X_SPAN * FLOOR_W);   // = v * 0.96，与原完全一致
const nY = v => Math.round(v / Y_SPAN * FLOOR_H);   // = v * 0.4，与原完全一致
```

因此：
- 既有 `0–1000` 的全部坐标（家具/墙/门/出生点/入口/外轮廓）**落点像素位置一字不差**；
- 右侧新增的 `1000–1500` 就是「东侧走廊 + 东侧服务翼」；
- 门洞净宽（h≈20px / v≈21px）、角色 22×55px、工位单元 51.2px 等**全部不变**，不会出现"画什么撞什么"的错位。
- 楼层外轮廓 `FULL_RECT / L24 / L56` 的右边线由 1000 延长到 1500，左下缺口保持。

> 想继续加宽只需改 `FLOOR_W` 与 `X_SPAN` 两个数（保持 `FLOOR_W / X_SPAN = 0.96`）。

## 3. 具体改动清单

### 3.1 楼板与外轮廓
- `FLOOR_W` 960 → **1440**；新增 `X_SPAN=1500 / Y_SPAN=1000`。
- `nX/nY` 改用各自设计跨度；墙段"端部守卫"公式同步改为按 `FLOOR_W/X_SPAN`、`FLOOR_H/Y_SPAN` 换算（否则门洞守卫会算错）。
- 三个外轮廓右侧边界 1000 → 1500。

### 3.2 东侧服务翼（7 层全部新增，设计文档最大缺口）
每层在东侧 `x 1000–1500` 新增：

| 家具 | 类型 | 坐标（归一化） |
|---|---|---|
| 东侧电梯厅 | cabinet | 1140,400,1300,560 |
| 东侧楼梯间 | cabinet | 1320,400,1470,560 |

4F 额外加「档案柜一/二」（强化档案票证主题，非容器、不改经济）。

### 3.3 竖向交通对齐（设计 §3.1 问题 A/B）
- 西侧 `stairLeft` 由 `x=185`（落在卫生间横带）统一改为 **`x=70`**（落进西侧核心筒），2F/3F/4F/7F 受益；y 取值使门点落在核心筒旁可站立处：1F/7F `y=700`，2F–4F `y=520`，5F/6F `y=250`。
- 东侧 `stairRight` 由 `x=930` 移到 **`x=1220`**（新东侧电梯厅旁）。
- 取消 3F/4F 原有的"左门重排到桌南空带"临时补丁（锚点已不再落在桌面遮挡足迹内）。
- **portal 稳定 ID / side / dir / target 全部未变**（`f{层}:portal:{side}-{dir}`）。

### 3.4 1F / 7F（自由发挥）
- 补上原本缺失的**西侧核心筒**（`cabinet 核心筒`）：1F `30,430,125,610`；7F `30,430,155,610`。
- 7F 的「更衣柜」升级为**可搜容器**（`container:locker`）——7F 此前 0 容器，搜寻维度是死层。

### 3.5 命名与常量
- `亲水间台面` → **`茶水间台面`**（2F–6F 共 5 处，对齐参考平面图）。
- 2F `储物柜` → **`核心筒`**（与 3–6F 一致）。

- `CONTAINER_IDS` 新增 `locker`（既有 9 个经济 ID 一字未改）。

### 3.6 可见性裁剪（连带修正）

## 5. 已知限制 / 后续可做

1. **东侧服务翼偏"空"**：目前是走廊 + 电梯厅 + 楼梯间 + 卫生间 + 装饰，属于"补齐参考图里缺的部分"；若想让每层更饱满，可在东侧再加 1–2 个功能房间。
2. **仍是程序化绘制**：电梯厅/楼梯间目前用 cabinet 造型，视觉上还不像"电梯"。需要美术侧按 `design/art/pixel-art-and-asset-guide.md` 的贴图路线替换。
3. **4F 只加了装饰柜**：设计建议的"4F 再加 1 个可搜容器"未做，因为它会影响筹码/搜寻经济，建议先定经济口径。
4. **容器总数由 9 → 10**：7F 新增 1 个，`CONTAINER_IDS` 已扩；如需保持 9 个可回退这一项。
5. **规则文档未同步**：`游戏规则.md` §12.2 仍写"六区域/当前仍四区"，与实际 7 层、已重构 ZONES 不一致，建议后续一并更新。
