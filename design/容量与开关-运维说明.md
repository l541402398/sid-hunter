# 容量与开关 · 运维说明

本文件记录 200–300 人峰值（极限 600）相关的能力、开关与实测数据。

## 一、开关一览

| 环境变量 | 作用 | 默认 | 适用场景 |
| --- | --- | --- | --- |
| `SID_AOI=1` | 只同步同层 + 视野内玩家；房间内外互相不可见 | 关 | 生产必开 |
| `SID_SKINS=1` | `colors` / `traits` 走 1Hz 的 `skins` 通道，不再每帧重发 | 关 | 生产建议开 |
| `SID_LOD=1` | 视野外圈按 5Hz 下发，内圈仍 20Hz（需同时开 AOI） | 关 | 生产建议开 |
| `SID_FLOOR_SCALE=N` | 楼层整体缩放倍数（`1` = 1440×400，`2` = 2880×800） | **2** | 已默认放大 |
| `SID_AOI_RADIUS=N` | AOI 半径（世界像素），默认跟随视野半宽（2× 时 720） | 720 | 一般不用改 |
| `SID_DURATION_MS=N` | 单局时长，默认 7 天 | 7d | 活动周期 |
| `SID_DB=0` | 关闭 SQLite 持久化 | 开 | 压测/临时环境 |

## 二、生产推荐配置

```bash
SID_AOI=1 SID_SKINS=1 SID_LOD=1 \
SID_FLOOR_SCALE=2 \
node online/server.js
```

> 浏览器端功能验收（`*-browser-test.mjs`）会在启动子进程时**强制把这些开关置 0**，
> 因为用例需要"看到所有玩家"。生产与测试的差异是刻意设计的。

## 三、300 人实测带宽（20Hz）

| 配置 | 单帧 | 每客户端 | 300 人合计 | 千兆网占用 |
| --- | --- | --- | --- | --- |
| 全量广播（旧） | 178 KB | 3.23 MB/s | 1020 MB/s | 816% ✗ |
| AOI | 28.3 KB | 0.54 MB/s | 169 MB/s | 135% ✗ |
| AOI + SKINS | 26.2 KB | 0.50 MB/s | 157 MB/s | 126% ✗ |
| AOI + SKINS + LOD | 15.5 KB | 0.30 MB/s | **72–91 MB/s** | 58–73% ⚠ |

复现方式：

```bash
node online/scale-test.mjs                                  # 全量
SID_AOI=1 node online/scale-test.mjs                        # AOI
SID_AOI=1 SID_SKINS=1 SID_LOD=1 node online/scale-test.mjs  # 三项全开
```

## 四、可见性分层规则

1. **同房间**：`zoneId` 相同才互相可见；房间内看不到走廊，走廊也看不到房间内；
2. **同层**：`floorId` 相同；
3. **视野**：横向 `|dx| <= AOI_RADIUS`，纵向 `|dy| <= AOI_RADIUS * 0.6`（斜俯视收缩）；
4. **自己**永远在名单里；
5. **排行榜**走独立的 `roster` 通道（1Hz 全员 id/名字/分数/存活），不受上述过滤影响。

专项测试：`node online/aoi-test.mjs`（11 项，覆盖房间隔离、跨层、半径边界、roster 完整性）。

## 五、已知边界

- 300 人实测 72–96 MB/s（多次取样，随机落点导致波动），**未达到 50 MB/s 目标**；
- LOD 在玩家集中于半屏内的分布下收益很小（远圈为空），视野内分散时才明显；
- 继续压缩需要削减每帧玩家投影（当前约 382 B/人，facing/lastAttack*/sid 等仍有空间）；
- `SID_FLOOR_SCALE=2` 已是默认值；浏览器通过服务端注入的 `window.__SID_FLOOR_SCALE__` 与服务端同比例（见 `server/http-util.js`），不会再出现两端错位；
- 镜头已按方案 B 拉远：一屏宽 = 半层（2× 时 1440 世界像素），房间内自动放大到整间铺满；
- 剩余浏览器套件失败（mechanics/rps/theme-assets/movement）是**改动前既有**的脚本/环境问题，与本轮缩放无关。
