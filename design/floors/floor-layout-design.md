## 0. 总览

### 0.1 七层定位与主题递进

一栋"从生活化迎宾层，逐层进入越冷静、越专业、越保密的工作层，最后登上明亮的健身/报告厅"的纵向叙事。

| 层 | 名称（世界内） | 主题定位 | 色彩基调（对齐 ART-01 §4） | 记忆点（一眼辨识） | 参考来源 |
|---|---|---|---|---|---|
| **1F** | 前台 · 大堂食堂 | 迎宾 + 生活化公共层（接待、等候、食堂、取餐） | 最暖最亮（暖木 + 米白 + 绿） | 前台接待台 + 6 张食堂餐桌 + 取餐台 | **原创提案** |
| **2F** | 综合办公 | 最大开放办公层，工位岛最多 | 中性偏冷（灰蓝 + 木） | 220 会议室 + 中央三排工位岛 | F2 真实图 |
| **3F** | 产品研发 | 研发/测试，讨论区密集 | 冷调 + 草绿点缀 | 301/302/303 连排会议 + 工位带 | F3 真实图 |
| **4F** | 档案票证 | 档案/票证，柜体与纸感最重 | 暖棕偏旧（纸箱/档案感） | 大量文件柜 + 416 作战室 | F4 真实图 |
| **5F** | 值班会议 | 值班 + 会议，长工位排 | 中性（灰 + 米） | 顶部长工位排 + 值班室 | F5 真实图 |
| **6F** | 财务会议 | 财务/管理，小会议簇 | 冷静专业（深蓝 + 灰） | 财务工位 + 三连小会议簇 | F6 真实图 |
| **7F** | 健身会议大厅 | 顶层放松 + 报告厅舞台（收官高潮） | 最明亮（绿胶地 + 木舞台） | 4 台跑步机 + 报告厅座椅 + 舞台 | **原创提案** |

**主题递进的一句话**：1F 欢迎你、喂饱你；2–4F 让你淹没在工位与文件里；5–6F 把你关进值班室与会议室；7F 是唯一"向上透气"的楼层——这也是玩家在楼层间逃逸、追逐时最自然的心理地图。

### 0.2 竖向交通体系（关键）

每层都有**两套竖向交通**，对应 `world.js` 的 `stairLeft`（西）与 `stairRight`（东）两个 portal 锚点：

| 体系 | 组成 | 参考图位置 | portal | 叙事定位 |
|---|---|---|---|---|
| **西侧核心筒** | 电梯 + 楼梯 + 西侧出口 | 各层左上（约 x 13–93，y 300–470） | `left-up` / `left-down` | 员工内部竖向通道；"最省事但最容易被堵"的路 |
| **东侧服务翼** | 东侧大门 + 电梯 + 楼梯 + 卫生间 | 各层右侧（约 x 875–1000，y 270–800） | `right-up` / `right-down` | 建筑主入口 + 东侧竖向通道；"正门进来先撞见人"的路 |

- 每层四扇门：`left-down / left-up / right-down / right-up`，由 `world.js` 第 475–478 行统一生成，**稳定 ID 规则 `f{层}:portal:{side}-{dir}` 不得改动**。
- 边界层禁用：1F 无 `down`、7F 无 `up`（`portalBoundaryReason` 已实现明确文本反馈）。
- 交互规则：进入 64px 且**面向门**（cos ≥ 0.5）才可提交，服务端权威（`portalAccess`）。

### 0.3 横向世界与"每层一屏"的适配

- 世界尺寸 **960 × 400 世界像素 / 层**；归一化 0–1000 → `nX(v)=v/1000*960`、`nY(v)=v/1000*400`（**约 2.4:1，非测绘**）。
- 相机默认让本人横向居中、到世界两端钳制；**每层在横向一屏内左右走完**，靠"上/下层"而非"同一层走远"制造纵深。
- 楼层外轮廓（0–1000 归一化，见 `world.js` 第 114–116 行）：
  - **FULL_RECT**（全矩形）：1F、7F。
  - **L24**（左下阶梯缺口）：2F、3F、4F —— 缺口对应参考图中"茶水间以南、226/316/416 斜角室以西"的建筑退台。
  - **L56**（更小的左下缺口）：5F、6F —— 对应参考图 5F/6F 的退台更小。
- **轮廓外禁止行走**（`inFloor` 多边形判定），不得用矩形底板"补平"缺口。

### 0.4 本文的坐标与标注约定

- 坐标一律 **0–1000 归一化**，格式沿用 `world.js` 家具行：`[type,label,x1,y1,x2,y2,flag?]`（`x` 向右=东，`y` 向下=南）。
- 每个坐标表都会标注三种口径：
  - **[参考]** = 从 `F2–F6.png` 量出的真实空间关系（权威）。
  - **[现状]** = `world.js` 当前已实现值（工程事实）。
  - **[建议]** = 本文给出的设计目标值（供用户/工程拍板）。
- 凡 **[建议]** 与 **[现状]** 不同者，均在 §3 一致性检查表与 §4 待确认清单中单列。

## 1. 通用设计语言

### 1.1 星露谷式像素办公表达原则

沿用 ART-01 的六条可执行特征（3/4 俯视、1px 硬描边 `#1c1620`、高饱和暖色、暖光锚点、材质区分、克制动画）。落到**布局**层面补充三条：

1. **"生活化堆料"是通行证**：每个功能区至少要有一件"非功能性装饰"（绿植/饮水机/公告板/挂画/地毯/垃圾桶）。空房间 = 不可读的房间。
2. **地面材质即分区**：木地板=开放办公，地毯=会议/讨论，瓷砖=走廊/卫生间，防滑胶=7F 健身区（对齐 ART-01 §3.3）。玩家不看文字也能读出"我到了哪"。
3. **房号牌与区域名统一制式**：`drawSign` 深棕+米白双层，房号统一 3 位数（`220/301/416/509/607`），区域名统一 2–4 字（`卫生间/茶水间/值班室/作战室`）。

### 1.2 可通行性硬约束（违反即视为缺陷）

| 约束 | 说明 | 依据 |
|---|---|---|
| **门是真实开洞** | 门 = 两段墙之间的空隙，不是贴图。`h` 门净宽 ≈ 20px（声明开口 40px），`v` 门净宽 ≈ 21px（声明开口 32px） | `world.js` 第 9–13、414–449 行 |
| **家具不封门口** | 房间家具（会议桌/工位）必须缩到房间一侧，**门口内侧留 ≥ 1 身位步道**（≥ 24px ≈ 0.75m）。历史教训：3F/4F 会议桌曾顶到门墙，已改为 `y ≤ 150` | `world.js` 第 172–173 行注释 |
| **家具足迹不封死通道** | 家具碰撞用 `blocksFor` 的**单体底部足迹并集**，不是整块 rect；连排工位岛按 `deskIsland` 生成（`WK_W=51.2px` 单元） | `world.js` 第 310–384 行 |
| **门口留步道** | 每扇门两侧墙端必须有可站立地面；portal 锚点若落在家具足迹内会被自动挪到最近可通行点（`mkPortal` 避障） | `world.js` 第 460–474 行 |
| **幽灵可穿家具** | 幽灵（淘汰态）穿家具、不越世界边界；布局不得依赖"家具当墙"来限制幽灵 | 规则 §8.2 |
| **不得隐形墙** | 不允许"看得见地板却走不进"。若矩形边界留下 < 1 身位死缝，用**真实共享实体**填满（先例：2F 205/206 之间的"工位绿植箱"） | `world.js` 第 160–162 行 |
| **不泄露身份** | 布局与装饰**不得**按玩家身份/阵营做任何差异（无"坏人专属房间"、无"仅好人可见的标记"） | 规则 §11 红线 1/3 |

### 1.3 交互点类型（布局只需提供"落点"，不新增机制）

| 交互点 | 触发方式 | 布局要求 |
|---|---|---|
| **可搜容器** `container` | 靠近 + 搜寻（每容器每人限一次） | 用 `flag='container:<name>'` 标记，保留既有稳定 ID；每层建议 1 个 |
| **NPC 线索兑换 / 大转盘** | 靠近 NPC 触发 | NPC 站位需**不在家具足迹内、不挡门口**；NPC 所在层提供筹码→线索与大转盘入口 |
| **猜拳** | 靠近任意玩家 64px 内 | 无需地图物件；但每层应有至少一处**开阔无遮挡区**供玩家面对面 |
| **电梯换层** | 靠近 portal + 面向门 + E | 西/东两套 portal 锚点（见 §0.2） |

> 转盘与猜拳均为 UI 层交互，**不需要**在地图上放"转盘机器"或"猜拳台"实体；布局只需保证落点可站立、可达、无遮挡。
