## 1. 现状诊断（Phase 0 结论）

游戏已实现 7 层办公楼（`online/shared/world.js` 的 `FLOOR_SPECS`，每层 960×400 世界像素，横向一屏，左右两侧 portal 上下层切换）。但存在以下**与参考图/自身不一致**的问题：

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| A | **东侧服务翼全楼缺失** | 高 | 参考图 2–6F 每层都有"东侧大门 + 电梯 + 楼梯 + 卫生间"，`world.js` 全部未实现（东侧只放了工位） |
| B | **西侧 portal 偏离核心筒** | 中高 | `stairLeft` 在 2F/3F/4F/7F 为 x=185，落在卫生间横带而非核心筒（x13–93）；5F/6F 的 x=70 才正确 |
| C | `stairLeft` y 跨层漂移 | 中 | 300/430/520/620 四种值并存，竖向交通不对齐 |
| D | 命名不一致 | 低 | `world.js` 用"亲水间"，参考图全部是"茶水间"；2F 核心筒叫"储物柜"、3–6F 叫"核心筒" |
| E | 全局 `ZONES` 常量过期 | 低 | 仍是 4 个旧区域名，与 7 层结构不符（规则 §12.2 已注"当前仍四区"） |
| F | 7F 无任何可搜容器 | 中 | 7F 在"搜寻得分"维度是死层 |

> 结论：2F–6F 的**骨架基本正确**（顶部会议室 → 核心筒 → 卫生间 → 茶水间 → 左下斜角室 → 底部房间带 → 中部工位岛），主要缺口是**东侧服务翼**与**西侧 portal 对齐**。

## 2. 设计要点（汇编）

### 2.1 七层定位与主题递进
1F 前台·大堂食堂（**原创**，最暖最亮）→ 2F 综合办公 → 3F 产品研发 → 4F 档案票证（暖棕回温）→ 5F 值班会议 → 6F 财务会议（最冷）→ 7F 健身会议大厅（**原创**，最亮收尾）。

### 2.2 竖向交通体系（关键）
- **西侧核心筒**（电梯+楼梯+西侧出口）+ **东侧服务翼**（东侧大门+电梯+楼梯+卫生间），与 `world.js` 的 `stairLeft`/`stairRight` 两套 portal 一一对应。
- 每层四扇门 `left-down / left-up / right-down / right-up`，稳定 ID 规则 `f{层}:portal:{side}-{dir}` 不变；1F 无 `down`、7F 无 `up`。
- 设计给出 **2–6F 统一竖向交通模板坐标**，把 B/C 两个问题收敛为"只改坐标、不改 ID"。

### 2.3 视觉方向（对齐星露谷）
- 统一 **48 色 SID 办公暖色板**（以 Lospec 的 Endesga 64 / Sweetie 16 为骨架），描边沿用 `#1c1620`，阴影改冷色 `#3a3350`。
- 瓦片基准建议 **32×32（=1m）**，对齐项目米制；地面因 2.4:1 进深压缩需预压扁或无缝平铺。
- 素材路线：**Kenney（CC0）+ 0x72/Ninja Adventure（CC0）+ 自绘/AI 补缺**为主；**LimeZu Modern Office（付费）**是最贴主题的补充；**The Spriters Resource 严禁商用**。
- 落地三步：地面/墙面贴图 → 家具 sprite（保持碰撞）→ 角色 spritesheet（必须 palette-swap 保身份可读性）。

## 4. 已知风险与缓解

| 风险 | 缓解 |
|---|---|
| **5 层长得像**（2–6F 同构骨架） | 每层地毯主色不同（2F 灰蓝/3F 草绿/4F 暖棕/5F 米灰/6F 深蓝）+ 电梯厅主题装饰物 |
| 东侧服务翼补齐 = 2–6F 东侧大改 | 需先确认不与 portal 避障、`safeSideLanding` 冲突；分阶段实施 |
| 素材授权 | 只采 CC0/明确授权；LPC(CC-BY-SA) 有传染性慎用；Spriters Resource 禁商用 |
| 投影错配（2.4:1 斜俯视） | 家具按 face+top+upright 重绘；地面预压扁 |
| 容器增减影响筹码/计分经济 | 4F/7F +1 容器需经济侧评估后再定 |
