# 《S-ID：年终生存战》像素美术方向与素材获取指南

> 文档编号：SID-FLOOR-ART-01 ｜ 负责人：林绘澄（美术方向）｜ 状态：待用户拍板
> 目标：把现有 Canvas 程序化绘制的 7 层办公室，统一到**星露谷（Stardew Valley）式温暖明亮俯视像素风**，并给出可直接采买的 CC0/可商用素材清单与渐进式落地路径。
> 约束：本指南只做视觉方向与素材规格，不改玩法数值、不写渲染逻辑代码；所有素材来源均标注授权，未核实项明确标"需自行核实授权"。

---

## 0. 摘要（一页版）

- **风格锚点**：星露谷 = 暖色高饱和 + 3/4 俯视 + 硬边描边 + 生活化堆料 + 克制动画（4 向 4 帧）。映射到办公室：木地板/地毯/瓷砖分区、暖木家具 + 布艺沙发 + 大量绿植、窗外黄昏暖光。
- **统一调色板**：以 Lospec 经典暖色板（Endesga 64 / Sweetie 16）为骨架，收敛为 **48 色 SID 办公暖色板**，与现有 UI（深蓝夜 `#0d1728` + 暖金 `#f0c47d`）和角色四色属性调色板兼容。
- **Tileset 规格**：世界公制为 **横向 32px/m、进深 13.33px/m（2.4:1 斜俯视）**，据此定 **32×32 为规范瓦片（=1m）**；地面因进深压缩，走"无缝平铺贴图"或"预压扁 32×13.33 地面瓦"两条路；图集按"每层一张 atlas + 全局共用 atlas"组织。
- **每层主题**：1F 暖木大堂食堂 → 2–4F 冷调办公（研发/档案用木+纸箱）→ 5–6F 中性会议 → 7F 明亮健身+舞台。
- **素材来源**：优先 Kenney.nl（CC0）、OpenGameArt LPC、0x72、Ninja Adventure（CC0）、Lospec（调色板）；LimeZu Modern Office（付费、最贴合）与 Sprout Lands（半免费）为高价值补充；**The Spriters Resource 仅供学习、严禁商用**。
- **落地路径**：程序化 → "先换地面/墙面平铺贴图" → "再换家具 sprite（保持碰撞不变）" → "最后换角色 spritesheet"。全程不破坏 `world.js` 的碰撞/深度语义。

## 1. 视觉身份

### 1.1 星露谷风格的六个可执行特征

| # | 特征 | 星露谷的具体做法 | 本项目的落地口径 |
|---|---|---|---|
| 1 | **视角** | 3/4 俯视（斜俯视）：地面被压扁，物体露出**正面立面**，能看到顶面 | 与现有一致：进深 13.33px/m 压扁、家具画 face + top + upright 三段（`drawFurnitureFace/Top/Upright`），沿用，不改投影 |
| 2 | **描边** | 全对象统一 1px 深色硬边（近黑带一点紫/棕），把角色/家具从地面"抠"出来 | 沿用现有 `#1c1620` 作为唯一描边色；新素材统一补/改此描边 |
| 3 | **饱和度与明度** | 高饱和但**不刺眼**：暖色系为主，阴影用冷色而非单纯变暗 | 从现有偏灰的"夜晚办公室"提亮一档：地板提亮约 +12%，阴影改用偏蓝紫（如 `#3a3350`）而非纯黑 |
| 4 | **光照** | 全局暖光 + 局部光源（台灯/窗光/招牌）形成暖黄光晕；窗外出落日暖色 | 复用现有 `glowSprite`（暖橙径向）与 `drawWindow` 的黄昏天空渐变；每层设 1–2 个"暖光锚点"（窗/灯/舞台） |
| 5 | **材质** | 每种材质有清晰纹理：木纹地板、瓷砖缝、地毯菱形、金属反光 | 见 §3.3 tile 清单：地板分木纹/地毯/瓷砖/防滑胶四种，各配 2–3 档色阶 |
| 6 | **动画节奏** | 克制：待机 2 帧、行走 4 帧、呼吸微动、影子随动；无夸张特效 | 沿用现有 `drawCharacterBody` 的 4 向 + 摆动 + 呼吸 bob；spritesheet 按 4 向 × 4 帧设计（§3.1） |

### 1.2 世界尺度约束（**所有美术规格的前提，务必先读**）

来自 `online/shared/world.js` 的硬数据：

| 参数 | 值 | 含义 |
|---|---|---|
| 每层世界尺寸 | **960 × 400 世界像素** | 相机/裁剪基准 |
| 水平/立面比例 | **32px / m** | 家具、门、角色高度都按此 |
| 平面进深比例 | **13.33px / m（2.4:1）** | 地面被纵向压扁，非测绘 |
| 角色身体（可见） | **约 22px 宽 × 55px 高** | `drawCharacterBody`：躯干 `x-11..x+11`，头顶到 `yb-49` |
| 角色碰撞 | 半宽 5.25 / 脚部 4+5 px | `BODY_HALF` / `FOOT_TOP` / `FOOT_BOTTOM` |

| 门洞 | h 门净宽 ~20px、v 门净宽 ~21px | 视觉门宽需 ≥ 此值，避免"看起来能过却过不去" |
| 家具类型 | desk / table / counter / cabinet / reception / sofa / plant / treadmill / rack / seat / mat / stage | 12 类，见 `FLOOR_SPECS` |

## 3. Tileset 规格

### 3.1 瓦片尺寸（推荐）

**规范网格：32×32 世界像素 = 1m。**

| 用途 | 尺寸 | 理由 |
|---|---|---|
| 地面·无缝平铺贴图 | **32×32**（或 16×16 2× 放大） | 与 32px/m 对齐；地面因 2.4:1 压缩，实际铺设时纵向按 13.33px 重复（见下） |
| 地面·分区瓦（地毯/瓷砖/地胶） | **32×13.33**（取整 32×14） | 预压扁，才能在地面网格里平铺而不变形 |
| 墙面 / 隔断 | **32×32** 起，墙段按长度横向拼接 | 墙高在立面按 32px/m，1m 墙 = 32px 高 |
| 家具/道具 | **32×32 网格对齐**，单件可 32×32 / 32×64 / 64×32 等 | 与家具单位 51.2px（1.6m）对齐；建议按 32 的倍数裁切 |
| 角色 spritesheet | **单帧 32×64**，4 向 × 4 帧 | 容纳 22×55 角色 + 头部/摆动余量；行走 4 帧（含 1 帧中段/接触），待机 2 帧 |
| 角色攻击/挥锤 | 单帧 64×64（独立 sheet） | 木锤挥击弧线超出身体框（现有 `drawCharacterAttack` 手部可达 ±40px） |
| 图标/UI | **16×16 / 32×32** | 背包/技能/状态图标 |

> **16 还是 32？** 结论：**规范用 32**（对齐项目米制）；若采用 Kenney/星露谷系 16×16 素材包，**统一 2× 最近邻放大到 32** 即可，全项目 `imageSmoothingEnabled = false`（现有已设），像素不糊。

### 3.2 图集（Atlas）组织方式

建议两张层级：

1. **全局共用 atlas（`atlas-common.png` + `.json`）**
   - 内容：地板 4 种材质 × 3 档、墙面 5 段、门框、绿植、台灯、告示牌、通用柜体、角色。
   - 尺寸控制：建议 **≤ 2048×2048**，兼容移动端 GPU 上限。
2. **每层差异 atlas（`atlas-f1.png` … `atlas-f7.png`）**
   - 只放该层独有的家具变体（如 7F 跑步机/哑铃架/舞台、1F 餐桌/取餐台、4F 档案柜）。

**元数据格式**：用 TexturePacker / free-tex-packer 导出的 **JSON（Hash 或 Array 格式）**，字段至少含 `x,y,w,h`，建议加 `pivot`（脚点/锚点）与 `padX/padUp/padDown`——**直接对应现有 `furniturePad(type)` 的 per-type 烘焙 padding 语义**，可无缝接入 `furnitureSprites` 缓存。

**命名规范**（与现有 ID 体系呼应）：
```
{品类}_{材质}_{变体}.png      例：floor_wood_a / wall_plaster_a / furn_desk_island
角色：char_{dir}_{frame}       例：char_front_0（dir: front/back/left/right）
```
现有家具 ID 形如 `f{层}:{type}:{index}`，建议 atlas 内的 key 与 `f.type` 对齐（`desk/table/...`），映射时按 `type + 变体` 取图。

### 3.3 每层需要的 tile 类型清单

**① 地面层（Ground）**
- 木地板：3 档色 × 横向宽板（32×8 板节奏，沿用现有）
- 地毯：会议区，菱形纹，3 档色
- 瓷砖：走廊/卫生间，1px 缝，2 档色
- 防滑胶：7F 健身区，1 档
- 地面过渡边（木↔瓷砖、地毯压边）各 1 组

**② 墙体层（Walls）**
- 墙段（横/竖）× 3 段（普通墙 / 玻璃隔断 / 门框）
- 门（横门 / 竖门）× 2 态（开 / 关）——**视觉门宽须 ≥ 现有净宽 h≈20px / v≈21px**
- 墙角、墙端收口
- 墙顶高光条 / 墙底阴影条（可程序化叠加，不必入图）

**③ 家具层（Furniture，按 `world.js` 12 类）**
| type | 需 tile | 备注 |
|---|---|---|
| desk | 工位岛（连排/双面）、工位单桌、房号竖桌、椅 | 与 `deskBranch` 三分支对应 |
| table | 会议桌（大/小）、食堂餐桌、讨论桌 | 食堂桌走 `drawDiningTable` 专用画法 |
| counter | 取餐台、卫生间台面 | 贴后沿一条碰撞 |
| cabinet | 储物柜、文件柜、核心筒、更衣柜 | 双开门 + 拉手 |
| reception | 接待台 | 台面高光 |
| sofa | 等候沙发 | 布艺 |
| plant | 门厅/食堂/工位绿植箱 | 生活化关键堆料 |
| treadmill / rack / mat / seat / stage | 跑步机/哑铃架/训练垫/座椅/舞台 | 7F 专用 |

**④ 装饰层（Decor）**
- 台灯、壁灯、吊灯、筒灯（暖光锚点）
- 告示牌 / 房号牌 / 区域名 / KPI 看板
- 挂画、时钟、白板、饮水机、垃圾桶、盆栽小件
- 窗（含黄昏天空 + 城市剪影，沿用 `drawWindow`）

**⑤ 角色层（Characters）**
- 4 向 × 4 帧行走 + 2 帧待机 + 挥锤/跳跃（可后置）

## 6. 落地路径（从"程序化绘制"渐进到"贴图/图集"）

**总原则：分三步走，每步都保持 `world.js` 的碰撞/深度/交互语义不变**（`blocks`、`footprint`、`depth`、`coverFor` 全部照旧）。渲染层从"纯程序化"过渡到"贴图优先、程序化兜底"。

### 阶段 A：地面与墙面先贴图（风险最低，收益最直观）
1. 把 `chunkFor` 的木地板平铺纹理换成**一张可无缝平铺的地板图**（32×32 或 16×16 2×），保留"分块烘焙 + LRU 缓存"机制不变——**只替换 `chunkFor` 里的 `fillRect` 画法为 `drawImage` 平铺**。
2. 按楼层/区域切换地板材质（木/地毯/瓷砖/地胶）：在 `FLOOR_SPECS` 上加一个只读字段 `floorStyle`（如 `'wood'|'carpet'|'tile'|'rubber'`），渲染时按区域矩形选纹理；**不改碰撞**。
3. `drawWallPanel` 换成墙贴图 + 程序化高光/阴影条叠加。
4. 验证：截图对比 QA 用例（`exploration-*` / `movement-attack-*` 的视觉断言若涉及颜色，需同步更新期望值）。

### 阶段 B：家具换 sprite（保持"画什么撞什么"）
1. 现有 `bakeSprites()` 已经**为每件家具烘焙一次 canvas**（`furnitureSprites` Map）。改造点：把 `drawFurniture(...)` 内部从"程序化矩形"改为"**按 `f.type`（+变体）从 atlas 取图 `drawImage`**"，其余逻辑（padding、blocks、footprint）不动。
2. 关键约束：**`deskBranch` 三分支（island/workSingle/roomSingle）与 `blocksFor` 的碰撞必须与贴图视觉一致**——即"贴图里的桌面"要覆盖"碰撞块"范围，避免"看着能走却撞墙"。建议贴图设计时就以 `blocks` 矩形为基准外扩。
3. 家具变体映射：给 `FLOOR_SPECS` 家具行加可选第 8 位 `sprite` key（如 `'desk_island'`），缺省按 `type` 兜底。

### 阶段 C：角色 spritesheet 化（最后做，最敏感）
1. `drawCharacterBody` 目前是逐块 `fillRect` 程序化绘制，含 4 向 + 摆动 + 呼吸 + 挥锤。改造为：**从角色 atlas 按 `spriteFacing` + 行走相位取帧**。
2. **身份可读性优先**：4 个属性色（hair/top/pants/shoes）必须在 sprite 里以**可换色的调色区**实现（用 palette-swap：sprite 用索引色，运行时按 `PALETTES` 替换），否则就退化成"每个玩家一套图"——不可接受。
3. 挥锤/跳跃（`drawCharacterAttack`）可**最后再换**，或先保留程序化（它已与 `ACTION` 数值同源），降低风险。
4. 回归：跑 `movement-attack-*` / `hammer-*` / `ghost-offline-*` 浏览器用例，确认朝向/摆动/遮挡无回归。

### 代码侧建议（最小侵入）
- 新增 `online/public/art/` 放图集与 JSON；新增一个 `ART` 模块做"atlas 加载 + 按 key 取帧 + palette-swap"，**只被 `game.js` 引用**，不改 `world.js`。
- 建一个 `PALETTE` 常量表（§2），把散落 hex 收敛，美术与代码共用同一真源。
- 保留所有程序化画法作为**兜底**：atlas 未加载/缺 key 时回退到现有绘制，保证"素材没到位也不崩"。

## 7. 风险与待用户拍板项

### 风险
1. **授权风险**：LPC 系（CC-BY-SA）有传染性，闭源商业项目慎用；The Spriters Resource 系原厂拆图**严禁商用**；itch/Craftpix/GameDevMarket/Unity 逐包授权不同，**必须逐包核实**。→ 建议以 **Kenney（CC0）+ 自绘/AI 补缺 + 必要时购 LimeZu** 为主路径。
2. **风格一致性风险**：多来源素材混用会"串味"。→ 强制**统一描边色 + 限色到 §2 调色板 + 统一 32 网格**，混用前先做"并排截图比对"。
3. **投影错配风险**：公开素材多为**正方形俯视或等距（isometric）**，本项目是 **2.4:1 斜俯视**，直接套用会"站不住"。→ 家具贴图按"face + top + upright"三段逻辑重绘或裁切，**地面贴图需预压扁**。
4. **性能风险**：大图集 + 多楼层纹理可能超移动端显存。→ 图集 ≤2048×2048、复用现有 LRU 分块缓存、按层懒加载。
5. **身份可读性风险**：角色 spritesheet 化若不做 palette-swap，会破坏 4 色属性投影。→ 阶段 C 用索引色 sprite。

### 待用户拍板（给选项，请选）
- **A. 瓦片基准**：✅ 推荐 **32×32（=1m，对齐项目米制）**；备选 16×16（更星露谷原生，需全项目 2× 放大）。
- **B. 素材路线**：
  - B1（最省心/纯免费）：**Kenney（CC0）+ 0x72/Ninja Adventure（CC0）+ 自绘补缺**，风格需统一改色。
  - B2（最贴合/含付费）：**购买 LimeZu Modern Office / Modern Interiors**，几乎开箱即用办公室主题，再配 Kenney 补 UI/音效。
  - B3（可控/成本高）：**全自绘**（Aseprite + §2 调色板），风格最统一但工作量最大。
- **C. 角色处理**：先保留现有程序化角色（阶段 A/B 只换场景）？还是同步做 spritesheet（阶段 C，需 palette-swap）？
- **D. AI 生成**：是否允许用 PixelLab/Scenario 生成补缺素材（需人工修描 + 商用条款核实）？
